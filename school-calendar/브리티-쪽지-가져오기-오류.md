# 브리티 지난 쪽지 가져오기 오류와 수정 내역

**2026년 11월 18일 기준 · 브리티 메신저 캘린더 일반판 0.5.10~0.5.11**

현재 수정·검증 상태와 다음 확인은 저장소 루트의 [진행 정리](../진행-정리.md)에서 갱신한다.

0.5.10의 ‘상세창 못 찾음’은 **수집기가 브리티 화면에서 본문 영역을 읽지 못했다**는 기록이다. 사용자가 눈으로 보는 쪽지창이 실제로 열렸는지, 어떤 모양이었는지까지 기록한 것은 아니다.

## 0.5.11에서 바꾼 부분

| 부분 | 기존 동작 | 변경한 동작 |
| --- | --- | --- |
| 쪽지 행 열기 | 창 안에서 ID가 맞는 요소를 찾아 실행을 요청하고, 요청의 성공 여부를 버렸다. | 쪽지 목록 안에서 ID가 일치하는 행이 하나일 때 그 행을 연다. 실행 요청이 통하지 않으면 Windows 접근성 기능으로 행 선택도 시도한다. |
| 본문 영역 찾기 | 처음 잡은 창 안에서 이름이 ‘상세 보기’인 그룹을 찾았다. 이 이름으로 찾지 못하면 본문 읽기가 실패했다. | 기존 방식으로 읽히지 않으면 ‘수신’ 표시에서 출발해 본문 문서가 하나인 영역을 찾는다. 현재 창과 새로 열린 브리티 창, 직전에 본문을 확인한 창이 탐색 대상이다. |
| 열린 쪽지 대조 | 목록에 표시된 내용과 상세 화면을 비교하고, 연속해서 같은 내용을 읽었는지 확인했다. | 대체 경로에서는 보낸 사람과 제목을 목록과 대조하고 기간 조회 시 받은 날짜도 확인한다. 본문이나 첨부가 있고 후보가 하나로 좁혀져야 한다. 첨부도 확인된 본문 영역에서 찾는다. |
| 진행 중단과 안내 | 확인된 쪽지가 0건이어도 열기를 시도한 항목이 남으면 같은 묶음을 최대 10회까지 반복할 수 있었다. | 한 묶음에서 열기를 시도했지만 원문을 하나도 확인하지 못하면 중단하고 해당 건수를 표시한다. 앞 묶음에서 이미 가져온 건수는 유지한다. |

별도로 **가져오기 진단 도구**를 만들었다. 기존 수집 기록을 읽어 목록 수, 열기 시도 수, 상세창 탐색 실패 수, 저장·등록 수를 보여 준다. 제보자는 쪽지 본문, 보낸 사람 이름, API 키를 공유하지 않고도 0.5.10의 실패 단계를 알려줄 수 있었다.

## 진단 3에서 확인한 실패 단계 (11월 18일 13:50)

첫 화면의 읽은 쪽지를 ID로 열 때와 날짜 검색으로 다시 찾을 때 모두 실행·선택 요청을 마쳤다. 날짜 검색에서 일치한 2건 중 실제 첫 항목은 시험 대상과 같았다. 날짜 해석 불가 3건도 있었지만, 날짜를 쓰지 않는 ID 경로에서도 같은 단계에서 멈췄다. 아래쪽 목록은 시험할 대상을 찾지 못해 첫 화면 항목으로 대체했다.

두 시험 모두 마지막 관찰에서 메인 창 하나와 문서 하나가 보였고, 열기 전후 문서 글자가 달라졌다. 기본 탐색이 찾는 ‘상세 보기’와 대체 탐색이 찾는 ‘수신’은 모두 0개였다. 따라서 제목·발신자 대조까지 진행할 후보가 없었다. 글자 변화만으로 대상 쪽지의 본문이 실제 화면에 표시됐는지는 판별할 수 없다.

제보 창은 462×709, DPI 96이었다. 앞서 성공을 확인한 가장 작은 창은 824×650, 배율 100%였다. 창 너비가 영향을 줬는지는 미확인이다. 최대화한 상태에서 같은 진단을 돌릴 때 화면에 본문이 보이는지도 함께 관찰하면 행을 눌러도 본문이 표시되지 않는 경우와 표시된 본문을 수집기가 찾지 못하는 경우를 구분하는 데 도움이 된다.

### 한 번 실행하는 쪽지 열기 진단 3 (11월 18일)

[전달용 ZIP](../outputs/브리티-쪽지-열기-진단.zip)을 풀고 브리티에 로그인한 상태에서 `쪽지-열기-진단.cmd`를 한 번 실행한다. 끝나면 메모장에 뜨는 `쪽지-열기-진단-결과.txt`만 받는다.

- **시험 대상** — 0.5.11의 수집 코드에 관찰 기록을 추가했다. 첫 화면의 읽은 쪽지 한 건은 ID로, 목록을 내려야 보이는 읽은 쪽지 한 건은 날짜로 찾아 연다. 날짜 시험에서는 원래 수집기의 첫 후보와 시험 대상이 같은지도 남긴다. 매번 열기 전에 행 ID와 읽음 표시를 다시 확인한다. 아래쪽에 적합한 대상이 없으면 첫 화면으로 대체한 사실 또는 생략 이유가 기록된다.
- **실패 판독** — 각 시험의 `판정`과 바로 앞 기록을 읽는다. 행 재탐색, 실행·선택 요청, 본문 후보 탐색, 목록 대조, 연속 두 번 같은 본문 확인을 구별한다. 대체 탐색을 사용한 경우 기존 창 제외, 날짜 형식, 보낸 사람·제목 일치, 후보 중복 등 관찰된 조건을 남긴다. 창별 문서 구조와 열기 전후 글자 변화도 함께 본다. 문서 변화만으로 특정 쪽지가 열렸다고 확정할 수는 없다.
- **기록 범위** — 결과에는 시각·버전·창 상태·배율(DPI), 건수·길이·일치 여부, 접근성 요소의 종류가 들어간다. 쪽지 ID·제목·보낸 사람·본문·첨부 파일명·화면 이름표 원문은 쓰지 않는다. 쪽지 JSON을 만들거나 첨부를 내려받거나 AI에 보내지 않는다.
- **검증** — 이 PC의 브리티 2.1.98.11에서 최종 ZIP을 풀어 실행했다. 첫 화면과 날짜 경로 모두 열기 전에 다른 쪽지가 표시돼 있었고, 두 시험 모두 목록 대조와 본문 안정성 확인을 통과했다. 날짜 경로는 날짜가 맞는 5건 중 실제 첫 후보를 시험했다. 가상 자료로는 본문 없음·대조 실패·본문 불안정·행 소실·읽음 상태 및 ID 변경을 포함한 8가지 판정을 확인했다. 제보 PC에서의 실패 원인은 그 PC의 결과를 받아야 알 수 있다.

특히 0.5.11은 가져오기 시작 전부터 열려 있던 별도 창을 대체로 탐색 대상에서 제외한다. 제보 PC에서 브리티가 그런 창을 재사용하는지는 미확인이다. 현재 근거로는 사용자에게 쪽지창을 항상 닫거나 화면 배율을 바꾸라고 안내할 이유가 없다.

## 진단 3 결과 (11월 18일 13:50, 제보 PC)

- **제보 PC** — 창 보임 462×709, DPI 96, 화면 2개, 브리티 2.1.98.11. 두 시험 모두 열기 요청 뒤 메인 창 문서 글자는 바뀌었지만 문서 1개(`Document<Pane…`)뿐이고 `상세 보기`·`수신` 이름표 0, 관찰된 새 창 없음. 날짜 해석 불가 3건. 실제 화면에 어떤 쪽지 본문이 표시됐는지는 확인되지 않았다.
- **이 PC 대조** — 같은 ZIP을 최소화(1280×720)와 띄운 창에서 실행해 모두 통과, 매번 문서 2개·이름표 1. 462×709로 줄이려 했지만 이 PC 브리티는 가로 824 아래로 줄어들지 않아(최소화 중에는 크기 변경 자체가 안 먹음) 재현하지 못했다. 시험 뒤 창은 원래 크기·최소화로 되돌렸다.

| 쪽지를 연 직후 프로그램 종료, 또는 첨부를 받는 도중 저장 공간 부족 | 본문과 자리표시 모두 열기 이후에 쓴다. 첨부 처리도 정상 본문 저장보다 먼저라서 그 사이 중단되면 캘린더에 흔적이 없을 수 있다. | 열기 요청 전에 ID와 목록 정보를 복구 가능한 형태로 저장한다. 기록에 실패하면 열기를 멈춘다. 확인된 본문을 먼저 안전하게 저장하고 첨부를 이어 받는다. |
| 같은 발신자의 비슷한 제목, 또는 제목만 먼저 보이는 느린 화면 | 자동 경로의 대조 함수가 제목 앞 8글자가 같은 이전 쪽지와, 본문·첨부가 모두 빈 상세를 각각 일치로 돌려줬다. 같은 화면이 연속으로 관찰되면 검증을 통과할 수 있다. | 전체 제목·발신자·받은 시각 등 구분 가능한 정보를 대조한다. 후보가 겹치거나 본문 로딩과 빈 본문을 구분할 수 없으면 목록 정보만 보이고 AI 분류를 보류한다. 첨부만 있는 쪽지는 해당 첨부와 대상의 일치를 확인하면 정상으로 처리한다. |
| 다른 다운로드가 쪽지 첨부와 동시에 끝남 | 브리티는 다운로드 버튼을 누른 뒤 가장 최근에 바뀐 파일을 고른다. 요청한 이름과 실제 파일을 대조하지 않아 다른 파일이 붙을 수 있다. 현재 ‘첨부만 다시 받기’는 GOE 기능이다. | 내려받기 전후 파일을 대조하고 예상 이름과 완료 상태가 맞는 후보 하나만 연결한다. 여러 후보면 첨부를 보류하고 브리티 쪽지에서도 해당 첨부만 재시도할 수 있게 한다. |
| 목록에서 발견한 행을 열기 직전에 다시 찾지 못함 | 저장 없이 끝난 시도도 미확인 건수에 포함되고, 연결 코드가 확인·미확인 수를 더해 ‘새 쪽지 N건 받음’으로 표시한다. | 캘린더에 실제 반영된 ID로 건수를 집계한다. 원문 저장, 목록 정보만 저장, 저장 실패를 구분한다. |
| 수집 중 선생님이 다른 쪽지 창을 엶 | 정리 시 시작 후 생긴 수신 쪽지 창들을 닫으므로 선생님이 방금 연 창도 조건에 들어갈 수 있다. 실제 사용자 창이 닫히는지는 이번 검토에서 시험하지 않았다. | 사용자가 조작을 시작하면 다음 열기를 보류한다. 수집기가 열었다고 특정할 수 있는 창만 닫는다. |

**기존 대응에서 바꿀 점**

- 연결 실패와 사용 중 보류는 다음 주기에 다시 시도한다. 오래 반복될 때 마지막 성공 시각과 실제로 확인한 실패 단계를 보인다. 검색칸 등 원인을 확인하지 못했으면 원인으로 단정하지 않는다.
- 첫 화면 아래의 쪽지는 한 번에 짧게 목록을 탐색하고 중단 위치를 기억해 다음 주기에 이어간다. 수집 가능한 범위를 다 확인했을 때만 새 쪽지가 없다고 안내한다.
- 기간 가져오기에도 열기 전에 같은 기록을 남긴다. 실패한 각 쪽지를 결과 화면에서 골라 다시 시도할 수 있게 하고, 기간 조회가 끝날 때까지 확인하지 못한 범위는 따로 표시한다.
- AI 장애 때는 원문을 유지하고 일시 오류는 제한적으로 재시도한다. 분류 호출이 성공해도 취소·정정 쪽지를 구분하지 못할 수 있다. 예전 일정과 충돌할 때 두 원문과 날짜를 함께 보여 주고 선생님이 반영을 결정하도록 한다.
- 안내와 실제 위치를 맞춘다. 현재 새로 생긴 미검증 쪽지는 ‘분류할 것 → 쪽지’에 표시된다. 이번 회귀 시험에서 재시작 뒤 정상 제목·원문 복구와 다운로드 폴더의 첨부 사본 한 개를 확인했다. 복구된 쪽지가 실제 앱에서 설정대로 분류되는지는 현장 확인에 남겼다.
