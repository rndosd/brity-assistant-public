# 반복 업무 설계

- **좋은 결과**: 매주·격주·매월 하는 일을 한 번 넣으면 학기 끝까지 달력에 놓이고, 회차마다 따로 끝낼 수 있다. 목록은 반복 때문에 길어지지 않는다.
- **기준**: 지금 업무 한 건이 하는 일(끝냄·중요·상시·메모·업무 시작·검색·백업)이 회차에서도 그대로 된다. 쪽지 분류(AI)는 건드리지 않는다.
- **상태**: 2026-11-20 줄인 1차안 구현(`DESIGN.md` 끝 2026-11-20 줄). 학사일정 쉬는 날 빼기까지 넣음.
- **AI가 확인할 것**: 아래 "시험" 절 전부, 실제 앱 창에서 추가→끝냄→이후 모두 고치기→반복 그만.
- **사람에게 물을 것**: 기본 끝 날짜를 학기 끝으로 둘지, 목록에 가까운 회차 하나만 보일지, 피드백 준 분의 실제 반복 업무 예시.

## 1. 저장: 회차마다 실제 업무 한 건 (규칙만 저장하지 않음)

처음엔 규칙 하나만 저장하고 화면에서 날짜를 계산하려 했다. 하지만 코드에서 끝냄(`setDone(id, index)`), 중요, 상시, 메모, 업무 시작(`prepareWork`), 검색, 달력 칸, 목록 줄이 모두 **업무 id + 날짜 순서** 기준이다. 가상 회차로 하면 이 모든 곳을 고쳐야 한다. 그래서 회차를 진짜 업무로 만들고 같은 반복끼리 묶음 표시를 단다.

회차 업무 = 보통 업무 + `repeat` 필드:

```js
repeat: {
  seriesId: 'uuid',                 // 같은 반복끼리 같음
  rule: { every: 'week' | '2weeks' | 'month',
          weekdays: [4],            // week·2weeks: 0=일 … 6=토, 여러 개 가능
          month: { day: 19 } | { nth: 3, weekday: 4 } | { nth: -1, weekday: 5 } },
  start: '2026-11-19', until: '2027-02-28',
  skip: ['2026-12-24'],             // 건너뛴 회차(다시 만들지 않게)
  on: '2026-11-26',                 // 이 회차의 원래 날짜
  edited: true                      // "이 회차만" 고친 적 있음(이후 모두 고치기에서 안 건드림)
}
```

- 규칙(`rule`·`start`·`until`·`skip`)은 같은 반복의 모든 회차에 똑같이 복사해 둔다. 따로 파일을 두지 않으니 백업·복원·옛 판에서 그대로 열린다. 옛 판에서는 보통 업무로 보인다.
- 날짜는 지금처럼 `dates` 한 줄이다(종류 마감·일정, 시간·교시 그대로). 기간+반복은 1차에서 막는다.
- 회차는 만들 때 `until`까지 한꺼번에 만든다. 최대 60회까지다. 학기 끝까지 매주면 15~20회라 tasks.json 부담이 적고, 나중에 몰래 만드는 배경 작업도 필요 없다.

## 2. 규칙 계산

- **매주·격주**: `start`가 있는 주부터 고른 요일. 격주는 `start`의 주를 기준으로 홀짝을 정한다.
- **매월 ○일**: 그 달에 그날이 없으면(31일 등) 그 달 마지막 날로 한다. 학교의 "말일까지 제출"에 맞다.
- **매월 ○째 ○요일**: 고른 날짜에서 자동으로 계산한다(19일 목 → 셋째 목요일). 다섯째 주가 되면 "마지막 ○요일"을 대신 제안한다.
- `skip`에 든 날짜는 만들지 않는다. 나중에 학사일정(방학·재량휴업)이 들어오면 같은 `skip`을 자동으로 채운다(2차).

## 3. 만들기: 업무 추가 창

날짜·종류 줄 아래에 한 줄을 더한다.

```
반복  [안 함 ▾]                         ← 안 함 / 매주 / 격주 / 매월
      (매주·격주) 월 화 수 [목] 금 토 일   ← 고른 날짜의 요일이 기본으로 켜짐
      (매월)  ○ 매월 19일  ○ 매월 셋째 목요일
      끝    [2027-02-28]  · 매주 목요일, 15회
```

- 끝 날짜 기본값은 학기 끝이다. 3~8월에 만들면 8월 31일, 9~2월이면 2월 말일. 끝없는 반복은 두지 않는다.
- 회차 수 미리보기를 보여 준다. 60회가 넘으면 끝 날짜를 당기라고 안내한다.
- 종류가 기간이면 반복 줄을 숨긴다.

### 줄인 1차안 (2026-11-19 사용자 "UI가 복잡해질까 봐 걱정") — 아래 3절·세 곳보다 우선

- 더하는 화면 요소는 셋뿐: ① 반복 고르기 칸 하나(안 함 / 매주 / 격주 / 매월, 고른 날짜의 요일·날짜 기준) ② 꼬리표 ↻ ③ 자세히에 한 줄 "↻ 매주 목 · 2/28까지 [반복 그만]".
- 반복 칸은 업무 추가 창과 자세히의 날짜 고치기(종류 칸 옆)에 같은 모양으로. 따로 [반복] 단추·관리 묶음은 만들지 않음.
- 요일 여러 개 고르기 없음(월·목이면 두 번 추가). 끝 날짜 칸 없음: 학기 끝 자동, 칸 아래 작은 글씨 "2/28까지 · 15회". 바꾸려면 자세히에서.
- "이 회차만/이후 모두"는 날짜·제목을 바꿀 때만 묻는다.

### 상시와 다른 점, 등록하는 세 곳 (2026-11-19 사용자 "상시랑 좀 다른 느낌으로 반복")

- 상시 = 업무 하나를 끝낼 때까지 목록 맨 위에 붙여 둠(D-day). 반복 = 주기마다 새 회차가 생겨 그 주의 "오늘·이번 주"에 들어오고, 끝내도 다음 회차가 또 온다.
- 등록: ① 업무 추가 창의 반복 줄 ② 이미 있는 업무 자세히의 [상시] 옆 [반복] 단추(쪽지에서 온 업무도, 그 날짜를 첫 회차로) ③ 목록 맨 아래 접힌 "반복 업무 n개" 묶음에서 관리(규칙 보기·고치기·그만).

## 4. 보이기

- **달력**: 모든 회차를 보통 업무처럼 그린다. 꼬리표 제목 앞에 작은 ↻를 붙이고, 마우스를 올리면 "매주 목요일 · 2/28까지"가 뜬다.
- **해야 할 것 목록**: 같은 반복은 **가장 가까운 남은 회차 하나만** 보인다. 지난 회차를 안 끝냈으면 그 회차는 "지남"에 따로 보인다. 그래야 "그 뒤"가 같은 줄 열다섯 개로 차지 않는다. 줄 끝에 ↻와 "다음 회차"를 표시한다.
- **끝낸 것**: 회차마다 한 줄씩 그대로 둔다(1차). 길어지면 묶는 것은 나중에 한다.
- **검색**: 같은 반복은 가장 가까운 회차 하나로 묶어 보여 준다.
- **자세히**: 날짜 줄 아래에 "↻ 매주 목요일 · 2027-02-28까지 [반복 고치기] [이번 회차 건너뛰기] [반복 그만]".

## 5. 고치기·건너뛰기·그만

- **회차를 고칠 때** 제목·날짜·시간·종류·메모를 바꾸고 저장하면 "이 회차만 / 이 회차부터 모두"를 묻는다.
  - 이 회차만: 그 업무만 고치고 `edited: true`로 표시한다.
  - 이 회차부터 모두: 이 회차와 그 뒤에서 **끝내지 않았고 따로 고치지 않은** 회차를 지우고, 새 값으로 다시 만든다. 끝낸 회차와 따로 고친 회차는 남긴다. 다시 만든 날짜가 따로 고친 회차의 날짜와 겹치면 고친 것을 남긴다.
- **반복 고치기**(요일·주기·끝 날짜 바꾸기)는 "이 회차부터 모두"와 같은 길이다.
- **이번 회차 건너뛰기**: 그 회차를 지우고 같은 반복 모든 회차의 `skip`에 그 날짜를 더한다.
- **반복 그만**: "앞으로 남은 n회를 지웁니다. 끝낸 회차는 남습니다"라고 확인한다. 그 뒤 오늘 이후에서 끝내지 않은 회차를 지우고 `until`을 어제로 바꾼다.
- 끝냄·중요·상시·업무 시작은 회차 하나에만 적용한다(묻지 않음).

## 6. 1차에서 안 하는 것

- 쪽지·대화방에서 "매주 ○요일" 문장을 반복 업무로 뽑기. 직접 입력만 받는다. 시간·교시 칸처럼 실제 쪽지로 시험한 뒤 정한다.
- 매일 반복, 하루에 여러 번, 기간+반복.
- 학사일정 자동 건너뛰기(2차, 학사일정 표시와 함께).

## 7. 손댈 곳

- `renderer/task-model.js`: `repeatDates(rule, start, until, skip)`(순수 함수), 규칙 확인.
- `store.js`: `create`에 반복 받기, `updateSeries(id, input, scope)`, `skipOccurrence(id)`, `stopSeries(id)`. `replace`는 `{...task, ...updates}`라 `repeat`가 남는다(확인함). 복원·불러오기 정리 경로는 시험으로 확인한다.
- `main.js`·preload: 새 IPC 세 개.
- `renderer/index.html`·`app.js`·`style.css`: 추가 창 반복 줄, 자세히 반복 줄과 "이 회차만/이후 모두" 확인, 목록·검색 묶기, ↻.
- `DESIGN.md` 끝에 결정 한 줄, `CHANGES.json`에 한 줄.

## 8. 시험

- 규칙 계산: 매주 여러 요일, 격주 홀짝, 매월 31일→2월 말일, 셋째 목·마지막 금, 해 넘김, `skip`, 60회 상한.
- 만들기→회차 수, 회차 하나 끝냄이 다른 회차에 안 번짐.
- 이 회차부터 모두: 끝낸·따로 고친 회차 보존, 날짜 겹침.
- 건너뛰기 뒤 이후 모두 고치기에서 다시 안 생김. 반복 그만 뒤 끝낸 회차 남음.
- 목록: 같은 반복 하나만, 지난 회차 따로. 검색 묶기.
- 백업 복원 뒤 `repeat` 유지.
- 실제 앱 창: 추가 창·자세히·목록 화면, 큰 글씨.
